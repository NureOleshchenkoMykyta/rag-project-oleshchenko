# Index Card — Векторний індекс та семантичний пошук (ЛР №3)

## 1. Загальна інформація
* **Проєкт:** RAG-система для пошуку відповідей у галузі програмної інженерії (`rag-project-oleshchenko`)
* **Призначення артефакту:** технічна специфікація моделі ембеддингів, параметрів векторного індексу, конфігурації пошуку та результатів базової оцінки ретривера.
* **Джерело даних:** підготовлений корпус чанків `data/processed/chunks.jsonl` (Software Engineering Stack Exchange, CC BY-SA 4.0).
* **Кількість проіндексованих чанків:** `4 716`

## 2. Модель ембеддингів
* **Назва моделі:** `sentence-transformers/all-MiniLM-L6-v2`
* **Архітектура:** 6-шаровий MiniLM (бі-енкодер на базі Transformer для семантичної близькості речень і фрагментів тексту)
* **Розмірність вектора (`embedding_dim`):** `384`
* **Нормалізація векторів:** L2-нормалізація (`normalize_embeddings=True`)
* **Розмір батчу при кодуванні:** `64`
* **Час кодування корпусу (4 716 чанків):** `106.86 с`

## 3. Векторне сховище та індекс
* **СУБД / бібліотека:** `ChromaDB` (локальний персистентний клієнт `PersistentClient`)
* **Директорія зберігання:** `data/chroma_db` (виключена з Git через `.gitignore`)
* **Назва колекції:** `se_stackexchange`
* **Алгоритм індексації та метрика:** HNSW, косинусна відстань (`hnsw:space = "cosine"`, подібність `sim = 1 - distance`)
* **Збережені метадані чанка:** `chunk_id`, `doc_id`, `chunk_index`, `total_chunks`, `title`, `source`, `license`
* **Час побудови індексу в ChromaDB:** `73.65 с`
* **Обсяг індексу на диску:** `63 271 692` байт (`60.34 МБ`)

## 4. Оцінка якості пошуку (Retrieval Evaluation)
* **Еталонний набір запитів:** `tests/eval-set.jsonl` (`20` запитів із розміченими релевантними `chunk_id`)
* **Метрики:** `Recall@5`, `Recall@10`

| Конфігурація пошуку | Фільтр метаданих | Recall@5 | Recall@10 | Коментар |
| :--- | :---: | :---: | :---: | :--- |
| **Baseline (основна)** | Без фільтра (`None`) | **0.8750 (87.5%)** | **0.9250 (92.5%)** | Оптимальна повнота пошуку по всіх чанках документа |
| **Експеримент 1** | `chunk_index == 0` | 0.8000 (80.0%) | 0.8250 (82.5%) | Зниження повноти через відсікання продовжень відповідей (`_c1`, `_c2`) |

## 5. Відомі обмеження та напрями покращення
* Частина семантично близьких дискусій із суміжних тредів (наприклад, щодо оцінки строків і нечітких вимог — запит `q13`) конкурує за верхні позиції видачі у суто векторному пошуку (`dense retrieval`).
* Подальше підвищення точності в top-5 можливе за рахунок гібридного пошуку (`BM25 + dense`) та/або етапу переранжування (`cross-encoder reranker`) у наступній лабораторній роботі.
